# 图像自动裁剪与 RGB 建模流程设计

## 1. 背景

当前项目已经完成 `water` 缓冲条件下的拍摄，图片位于 `Photo/` 目录，并按 `blank`、`single`、`binary`、`ternary` 四类分组存放。后续项目不会只停留在 `water` 一种缓冲，未来可能接入 `3` 种或 `4` 种缓冲。

在第一版实现后，又进一步明确了一个更合理的数据流程：

- 不再直接在原图上标注 ROI
- 先自动识别并裁剪出比色皿
- 正式保存裁剪图
- 只对异常裁剪图进行人工修正
- 再在裁剪图上标注 ROI 并提取 RGB

因此，本次设计将系统升级为一个轻量项目制的“两阶段图像处理系统”。

## 2. 目标

本阶段系统需要完成以下目标：

- 扫描原图并解析样本命名信息
- 批量自动识别比色皿并导出裁剪图
- 自动生成异常待修正列表，并支持人工补充
- 支持在原图上修正异常裁剪框
- 支持在裁剪图上标注 ROI
- 基于裁剪图批量提取 `RGB mean/std`
- 正式保存项目状态，后续可继续打开并复用

## 3. 新的总体流程

新版流程固定为以下 `5` 步：

1. 扫描 `Photo/` 原图并解析文件名元数据
2. 批量自动裁剪比色皿，保存到裁剪图目录
3. 自动生成异常待修正列表，允许人工追加异常图
4. 对异常图修正裁剪框，并刷新对应裁剪图
5. 在裁剪图上标注 ROI，批量提取 RGB，导出结果表与预览图

这一流程的核心原则是：

- 原图负责“识别比色皿”
- 裁剪图负责“标 ROI 和取色”
- 结果表负责“作为建模输入”

## 4. 文件命名解析规则

文件名格式为：

`<buffer_name>_<group_type>[_<tc,otc,ctc>][_<repeat_suffix>]`

示例：

- `water_blank.jpg`
- `water_blank_1.jpg`
- `water_single_60,0,0.jpg`
- `water_binary_6,54,0_2.jpg`
- `water_ternary_6,18,36.jpg`

解析字段包括：

- `buffer_name`
- `group_type`
- `tc_conc_uM`
- `otc_conc_uM`
- `ctc_conc_uM`
- `replicate_id`
- `sample_name`

重复编号映射规则：

- 无后缀 -> `R1`
- `_1` -> `R2`
- `_2` -> `R3`
- `_3` -> `R4`

## 5. 项目制持久化结构

系统不再只输出一次性结果，而是保存完整项目状态。

建议目录结构如下：

```text
Photo/
docs/
src/
project_data/
  project.json
  cropped_cuvettes/
  previews/
  rgb_results/
```

其中：

- `project.json`：项目主文件
- `cropped_cuvettes/`：正式保存的比色皿裁剪图
- `previews/`：ROI 标注预览图
- `rgb_results/`：结果表

## 7. 自动裁剪策略

第一版自动裁剪不追求通用到所有场景，而是针对当前实验拍摄条件进行稳健识别：

- 单图只有 `1` 个比色皿
- 黑背景
- 比色皿是明显的竖直亮区域
- 机位与构图基本固定

推荐策略：

1. 将原图转为灰度图
2. 对亮区域进行阈值分割
3. 找外轮廓
4. 根据面积、长宽比、位置筛选候选框
5. 选择最像“竖直比色皿”的候选框

自动裁剪输出两套框：

- `auto_rect`：程序自动识别结果
- `final_rect`：最终采用结果

默认情况下：

- `final_rect = auto_rect`

如果人工修正过，则只改 `final_rect`。

## 8. 异常图判定

系统先全量自动裁剪，再自动筛出值得人工检查的图。

第一轮建议采用规则型异常判定，包括：

- 宽度异常
- 高度异常
- 横向位置异常
- 纵向位置异常
- 过于贴近图像边界
- 自动检测失败

异常来源分为两类：

- 程序自动标记
- 用户手动加入异常列表

异常状态采用：

- `pending`
- `fixed`
- `ignored`
- `auto_ok`

## 9. 裁剪图作为主数据对象

这是本次改造最关键的结构变化。

后续所有 ROI 标注与 RGB 提取都基于裁剪图，而不是原图。

这样做的好处：

- 标注更直观
- 抽查更快
- ROI 坐标更稳定
- 不同批次原图尺寸变化时影响更小
- 后续多缓冲拼接更自然

## 10. ROI 与 RGB 提取策略

ROI 不再相对原图保存，而是相对裁剪图保存。

取色策略如下：

- ROI 位于液体中下部
- 避开液面弯月面
- 避开边缘高光
- 对 ROI 内像素按亮度做裁剪
- 去掉最亮和最暗的一部分像素
- 计算 `RGB mean/std`

每张裁剪图输出：

- `roi_mean_r`
- `roi_mean_g`
- `roi_mean_b`
- `roi_std_r`
- `roi_std_g`
- `roi_std_b`
- `pixel_count`
- `kept_pixel_count`
- `warning`

## 11. GUI 设计

GUI 改为三个工作阶段：

### 11.1 阶段 1：原图裁剪

功能包括：

- 选择原图目录
- 创建项目
- 批量自动裁剪比色皿
- 查看原图上的自动框与最终框
- 查看对应裁剪图
- 手动把某张图加入异常列表

### 11.2 阶段 2：异常修正

功能包括：

- 只显示待修正异常图
- 在原图上拖拽修正裁剪框
- 保存当前修正
- 标记为已修正
- 保持自动结果并忽略
- 切换手动异常标记

### 11.3 阶段 3：ROI 取色

功能包括：

- 浏览正式裁剪图
- 在裁剪图上标注 ROI
- 保存全局 ROI 配置
- 批量提取 RGB
- 查看结果表与标注预览图

第一轮完成后，至少满足以下条件：

- 能扫描当前 `105` 张 `water` 图片

- 能批量导出 `RGB` 结果表和预览图
- 项目重新打开后，裁剪结果、异常状态和 ROI 配置都能恢复

## 15. 后续与建模的衔接

本阶段系统的职责是：

`原图 -> 正式裁剪图 -> ROI -> RGB 结果表`

后续建模模块再负责：

1. 读取多个缓冲的 RGB 结果表
2. 按 `sample_name + replicate_id` 对齐
3. 生成联合特征
4. 生成 `tc_present`、`otc_present`、`ctc_present`
5. 开展探索分析与模型训练

最终宽表可以继续扩展为：

- `water_R/G/B`
- `tris6_R/G/B`
- `tris7_R/G/B`
- `tris8_R/G/B`

这样图像处理模块和建模模块边界清晰，便于后续持续扩展。
